# 实机验收记录与步骤

状态：当前 C84017 芯片读写闭环已完成并恢复备份；其他芯片及物理异常拔插待验收。下列步骤保留为后续型号的验收清单。

## 第一步：只接编程器

安装 udev 规则、拔插设备，打开 GUI，开启“记录 USB 请求与响应”，连接实机。
确认接口 0 查询 10–13 成功，保存原始 TX/RX。若响应解析不匹配，先根据真实字节修正解码器，不跳过 CRC / 长度错误继续烧录。

## 第二步：接入已知型号芯片

记录芯片完整丝印、封装、电压、夹具 / 转接座、接线和设备版本。选择型号并检查 1.8 V 适配器。
先识别，再全片读取两次，分别另存为两个 BIN，比较大小及 SHA-256；不能用“全 FF”本身当成连接成功的证据。

## 第三步：允许破坏内容的测试芯片

先保留备份。依次测试全片擦除 / 查空、写入非均匀测试数据、强制回读校验、保存回读文件并在程序外比对。
使用跨页 / 跨 4 KiB 的数据；较大芯片要覆盖 16 MiB 地址边界。进一步测试 NOR 未擦除写 0→1 的失败检测、EEPROM 改写和清空。

## 第四步：异常处理

检查读取中停止、写入中停止、设备拔出、超时、短包、错误 CRC；确认错误不会显示“完成”，既有缓冲区不会被部分读取覆盖。
硬件擦除取消不保证停止芯片内部操作，等待设备稳定后再重新连接和确认内容。

## 通过标准

- 真实响应封装经过确认。
- 至少一颗 SPI NOR 和一颗 I²C EEPROM 完成上述数据闭环；未测型号仍不能标为已验证。
- 大容量、1.8 V、第二插座和不同 flags 变种分别记录，不从单颗芯片结果外推。

2026-10-06：udev 权限已配置。使用与 GUI 相同的 Programmer 后端执行 `--probe-info`，四条设备信息查询通过。实机返回信息为 XTW5F-1.1.5.R1、XTW5-0.1.0、XTW-5。信息响应使用零尾部，已据此修正解析并加入抓包回归测试。

离线协议向量、模拟生命周期及 GUI 自动化测试已通过；后续实机读写结果见下文。原始报文和固件备份仅在本地保留，不公开发布。

`e4da6aca1e5c4c3f8e4ff413a7414a422b728dbe8b347646ae65d42dafbf6ee5`

文件包含 256 种字节值，非全 FF、非全零。备份和报文位于 `gd25q64c-read-a.bin`、`gd25q64c-read-b.bin` 及对应 `.log`。这些测试通过与 GUI 共用的 Programmer 后端执行，没有发送 32 / 35 擦写命令。重复读取一致不代表已验证写入、擦除或芯片所有变体。

## 2026-10-06：经用户授权的擦写测试（已恢复）

- 用户明确允许擦写当前芯片，并要求完成后恢复备份；GUI 已由用户断开，测试工具独占接口。
- 修改前 `verify-before-write.log`：整片校验与原备份一致。
- `verify-negative.log`：只在内存里翻转期望数据末字节，实际芯片不变；正确报告 007FFFFF 期望 FE、实际 FF。
- `erase-test-2.log`：擦除完成并全片查空通过。

### 最终恢复核对

`restore-original.log` 以 `PASS write` 结束，全部 8388608 字节校验通过。随后独立打开设备，保存 `restored-original-read.bin`；cmp 与最初 `gd25q64c-read-a.bin` 逐字节一致，SHA-256 均为 `e4da6aca1e5c4c3f8e4ff413a7414a422b728dbe8b347646ae65d42dafbf6ee5`。原芯片内容已恢复。
